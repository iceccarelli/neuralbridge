3 · What this report does not establish

Checkable offline from the ledger and this page: that every record hashes to its recorded value and links to its predecessor; that each finding reproduces when the engines are re-run on the same records (assurance machinery check); and, given a signer's key obtained independently, that the signed head matches. Not establishable from this artefact: that the records describe the machines as they physically are, that evidence was produced on the machine it is filed under, that a missing record never existed, or the correctness of any supplier statement.

Carried verbatim from the engines that produced the findings above. A report that hides its own limits is worth less than no report, because somebody will rely on it.

  1. no interventions were supplied for this machine. A function shown as current is current only against the change records you have; an unrecorded change is invisible here by construction.
  2. ITM-ZONES is safety-bearing and modifiable on site; coverage for SF-01 rests on every such change having been recorded.
  3. this joins verification bundles to intervention records through the safety functions the manifest declares. It does not confirm the manifest is complete, and a safety-relevant item nobody listed is covered by nothing here and reported by nothing here.
  4. The guard covers outbound connections made by this Python process through the socket module (connect, connect_ex, create_connection, sendto, and getaddrinfo). Every Python HTTP and TLS client goes through that layer.
  5. It does not cover a subprocess, which has its own socket layer. This run spawned none.
  6. It does not cover a C extension that opens a socket file descriptor without going through the socket module.
  7. It records intent, it does not enforce containment. Code determined to evade it could. Containment is a firewall's job; this answers whether the tool tried.
  8. COMPLETE, in this run's headline, means only that every item the collection plan names was found in an export folder and hashed. It does not say the plan names everything that is safety-relevant, that the files are current, that they came off the machine, or that anything was verified.
  9. This run recorded what was in the export folders at one moment. Nothing here watches for the next change; a firmware update tomorrow strands every sign-off in this ledger and nothing will say so until somebody runs this again.
  10. No supplier advisory was matched against these machines. A component with a published vulnerability would appear in this manifest as an ordinary item.
  11. The head of this ledger is not signed. A hash chain detects editing, not deletion: whoever holds this database can remove records and rebuild a chain that verifies. The attestation request written beside the report is the first half of closing that.
  12. No physical behaviour was verified. Nothing here says a machine stops in the distance its datasheet claims; that needs a recorded run against a declared safety envelope.
  13. Manifests were read from exported files, not from the machines. They are labelled supplied_by_vendor (tier ceiling community): the files are as good as the export, the export is as good as whoever produced it, and a folder of files cannot show which machine it came from. Such a manifest is not accepted as a look at the machine by the change workflow or by hosted ingest.

How to check this without trusting whoever sent it. Every finding above comes from a hash-chained ledger. Run assurance machinery check <passport> --ledger <register.db> against the ledger this was generated from: it re-runs the engine on the original records and reports any statement that does not reproduce.

Coverage joins verification bundles to intervention records through the safety functions the manifest declares. A verification is dated by when the run happened, not when it was filed. A function that declares no verification check is reported as not demonstrable, never as covered.

Nothing in this report is legal advice. Whether a changed configuration amounts to a substantial modification requiring a new conformity assessment is a question for the manufacturer and, where one is involved, the notified body.

This report is a record of what was collected, sealed and verified, and of what that evidence no longer supports. It is not a declaration of conformity and not a certification, and it does not say that any machine is safe. Where it shows evidence as current, that means no change has been recorded since the verification run was recorded; the run is not bound to the configuration found, and nothing more is claimed.
